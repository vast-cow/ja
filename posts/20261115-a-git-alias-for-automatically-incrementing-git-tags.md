Git でバージョン管理をしていると、`v1.2.3` のようなタグを付ける機会があります。

毎回、既存のタグを確認して、最新のバージョンを調べて、patch バージョンを +1 して、新しいタグを作るのは少し面倒です。

そこで、`git tag-bump` という Git alias を作って、**コマンド1つで次のバージョンのタグを作成できるようにします。**

## やりたいこと

例えば、以下のタグが存在しているとします。

```text
v1.0.0
v1.2.3
v1.2.9
v1.2.10
```

この状態で、

```bash
git tag-bump
```

を実行すると、最新の `v1.2.10` の patch バージョンをインクリメントした `v1.2.11` が作成されます。

## Git alias の登録

以下を一度だけ実行します。

```bash
git config --global alias.tag-bump '!f() { git tag "$(git tag -l "v*.*.*" --sort=-version:refname | awk -F. '"'"'/^v[0-9]+\.[0-9]+\.[0-9]+$/ {print $1 "." $2 "." ($3+1); exit}'"'"')"; }; f'
```

これで設定は完了です。

以降は、対象の Git リポジトリで次のコマンドを実行するだけです。

```bash
git tag-bump
```

作成されたタグは、次のコマンドで確認できます。

```bash
git tag -l 'v*.*.*' --sort=-version:refname
```

## 仕組み

登録したコマンドは、引用符を整理すると以下のようなシェルスクリプトになっています。

```bash
f() {
  git tag "$(
    git tag -l "v*.*.*" --sort=-version:refname |
    awk -F. '/^v[0-9]+\.[0-9]+\.[0-9]+$/ {
      print $1 "." $2 "." ($3+1);
      exit
    }'
  )"
}
f
```

順番に見ていきます。

### 1. バージョン形式のタグを列挙する

```bash
git tag -l "v*.*.*"
```

`v*.*.*` にマッチするタグを列挙します。

### 2. バージョン順でソートする

```bash
git tag -l "v*.*.*" --sort=-version:refname
```

`version:refname` は、Git が提供しているバージョン番号を考慮したソート方法です。

先頭の `-` によって降順にしています。

```text
v1.2.10
v1.2.9
v1.2.3
v1.0.0
```

通常の文字列ソートでは `v1.2.9` が `v1.2.10` より大きいと判定されることがありますが、バージョンソートなら数値を考慮して並べられます。

なお、`version:refname` は厳密な SemVer パーサーではありませんが、今回のような `v数字.数字.数字` 形式には適しています。

### 3. patch バージョンをインクリメントする

```bash
awk -F. '/^v[0-9]+\.[0-9]+\.[0-9]+$/ {
  print $1 "." $2 "." ($3+1);
  exit
}'
```

`awk` を使って、タグの patch 部分を +1 しています。

`-F.` は、`.` を区切り文字として扱う指定です。

例えば `v1.2.10` であれば、

| フィールド | 値 |
|---|---|
| `$1` | `v1` |
| `$2` | `2` |
| `$3` | `10` |

となります。

`$3+1` によって patch をインクリメントし、`v1.2.11` を出力します。

また、正規表現で `v1.2.3` のような形式だけを対象にしているため、`v1.2.3-rc.1` などのプレリリースタグは除外されます。

`exit` により、最初に見つかった有効なタグだけを処理します。

### 4. 新しいタグを作成する

最後に、シェルのコマンド置換 `$(...)` を使い、生成されたバージョンを `git tag` に渡します。

```bash
git tag "$( ... )"
```

これによって、現在の `HEAD` に新しいタグが作成されます。

## なぜ Git alias に `!` を付けるのか

Git alias は通常、Git のサブコマンドの省略形として使います。

例えば、

```bash
git config --global alias.st status
```

と設定すると、`git st` で `git status` を実行できます。

一方、先頭に `!` を付けると、Git のサブコマンドではなく、シェルコマンドとして実行できます。

今回はパイプや `awk`、コマンド置換を使用するため、`!` を付けています。

また、登録コマンド中の `'"'"'` は、シングルクォートで囲まれた文字列の内部にシングルクォートを含めるためのシェルの記法です。

## 注意点

この alias を使う際には、いくつか注意点があります。

- **既存タグが必要**：最初のタグを作成する処理は含まれていないため、対象となるタグが1つもない場合はエラーになります。
- **ローカルタグが対象**：リモートのタグを取得していない場合は、事前に `git fetch --tags` を実行します。
- **作成されるのは lightweight tag**：annotated tag が必要なら、`git tag -a` などへの変更が必要です。
- **タグの push は別途必要**：新しいタグはローカルに作成されるため、リモートへ反映する場合は `git push origin v1.2.11` のように実行します。
- **major / minor は変更しない**：常に最新バージョンの patch 部分のみをインクリメントします。

## まとめ

Git に標準で備わっている `--sort=-version:refname` と `awk` を組み合わせるだけで、外部のバージョン管理ツールに依存せずにタグのインクリメントを自動化できます。

一度 Git alias を設定すれば、普段の操作はこれだけです。

```bash
git tag-bump
```

ちょっとした自動化ですが、リリース時に繰り返す操作を減らせるので便利です。
